# Дизайн-система и каркас вёрстки

Как устроена публичная часть сайта: где живут токены, откуда берутся шрифты, из каких компонентов собирается страница и что делать, когда сайт открылся без стилей.

> **Вёрстка страниц ещё не закончена.** Веха 4.1 собрала каркас — шапку, подвал, карточку авто и форму заявки; веха 4.2 — главную, веха 4.3 — список каталога и карточку автомобиля. Автосервис и запчасти приходят вехой 4.4, «О компании» и контакты — 4.5. Страницы `/services`, `/parts` и `/contacts` сейчас заглушки: заголовок, вводный текст из настроек и форма. До своих вех публичная часть в релиз не идёт.

## Токены

Источник истины — блок `@theme` в [`resources/css/app.css`](../resources/css/app.css). Tailwind v4 конфигурируется в CSS, **файла `tailwind.config.js` в проекте быть не должно**.

Значения перенесены из UI Kit макета (`assets/Макет сайта «ЛАО КАРС»/UI Kit.dc.html`). Сверяться с макетом при вёрстке стоит по смыслу, а значения брать из токенов: оттенок, правленный в одном месте из двух, разъезжается в первый же раз.

| Токен | Утилиты | Значение | Где в макете |
| :---- | :---- | :---- | :---- |
| `--color-page` | `bg-page`, `text-page` | `oklch(0.13 0.004 60)` | фон страницы |
| `--color-page-alt` | `bg-page-alt` | `oklch(0.16 0.005 60)` | фон чередующейся секции |
| `--color-surface` | `bg-surface` | `oklch(0.185 0.006 60)` | фон карточки |
| `--color-deep` | `bg-deep` | `oklch(0.1 0.004 60)` | подложка бегущей строки |
| `--color-accent` | `bg-accent`, `text-accent` | `#f9c227` | CTA, цены, статусы, активные состояния |
| `--color-accent-hover` | `hover:bg-accent-hover` | `#fbd04f` | наведение на акцентные элементы |
| `--color-ink` | `text-ink` | `oklch(0.97 0.003 60)` | основной текст |
| `--color-ink-muted` | `text-ink-muted` | `oklch(0.68 0.01 60)` | вторичный текст |
| `--color-ink-faint` | `text-ink-faint` | `oklch(0.5 0.01 60)` | подписи, копирайт |
| `--color-photo` | `bg-photo` | `oklch(0.87 0.01 60)` | подложка под фото до загрузки |
| `--color-danger` | `text-danger` | `oklch(0.68 0.19 25)` | ошибка валидации |
| `--font-display` | `font-display` | Unbounded | заголовки, цены, числа |
| `--font-sans` | по умолчанию | Manrope | весь остальной текст |
| `--radius-card` | `rounded-card` | 18px | карточки и панели |
| `--radius-field` | `rounded-field` | 10px | поля форм и квадратные кнопки |
| `--container-page` | `max-w-page` | 1440px | ширина, в которой нарисован макет |

Полупрозрачных вариантов акцента отдельными токенами нет — подложка 14% и обводка 50% из макета пишутся как `bg-accent/14` и `border-accent/50`. Радиус кнопок и тегов (999px) — штатный `rounded-full`.

**Правила макета, которые токены не выражают:**

- не более двух фоновых оттенков на экране (`page` плюс один из остальных);
- один акцентный цвет — для CTA, цен, статуса «в наличии», активных состояний и одного-двух слов в заголовке; большие площади им не заливаются;
- наведение — подъём на 2–6px плюс тень или обводка, `0.2–0.25s`, не больше двух свойств одновременно, без пружинящих easing.

### Почему фоновый токен называется `page`, а не `base`

Пространства имён `--color-*` и `--text-*` в Tailwind v4 порождают один и тот же класс. Токен `--color-base` перебивает штатный размер шрифта `text-base` — `.text-base` начинает красить текст в цвет фона вместо того, чтобы задавать `1rem`. Собирается это без единой ошибки, а вылезает на первом же элементе, которому нужен размер.

То же правило действует для любого нового токена: имя не должно совпадать с ключом другого пространства имён Tailwind.

### Палитра Tailwind по умолчанию обнулена

В `@theme` стоит `--color-*: initial` — классов вида `text-gray-400` или `bg-red-500` в сборке нет вовсе. Случайный оттенок мимо дизайн-системы не доезжает до прода, потому что его просто нет.

Обнуление сделано вехой 4.3, и условие для него было названо заранее: переверстан последний функциональный шаблон (`catalog/index`, `catalog/show` больше не держатся на `text-gray-500`) и заменён вендорный вид пагинации, чьи светлые классы приходили в сборку через `@source`.

**Порядок внутри `@theme` обязателен:**

```css
@theme {
    --color-*: initial;   /* сначала вычистить пространство имён целиком */
    --color-white: #fff;  /* потом вернуть эти два вручную */
    --color-black: #000;

    --color-page: …;      /* и только потом токены макета */
}
```

`--color-*: initial` уносит вместе с серыми и `white` с `black`, а на них держится вся вёрстка проекта: `border-white/8`, `border-white/10`, `border-white/15`, `border-white/20`, `bg-white/6`. Исчезают эти классы **молча** — сборка зелёная, ошибок нет, просто пропадают все обводки карточек, полей формы и шапки.

Отсюда правило приёмки любой правки этого блока: не «выглядит так же», а поиск `border-white` в собранном CSS.

```bash
npm run build
grep -o 'border-white' public/build/assets/app-*.css | wc -l   # должно быть больше нуля
grep -c 'text-gray-' public/build/assets/app-*.css             # должно быть 0
```

Панель Filament этим не задета — у неё собственная сборка и собственная тема.

## Шрифты

Unbounded (заголовки) и Manrope (текст) **скачиваются на сборке и отдаются со своего домена**. Подключения к `fonts.googleapis.com` в рантайме нет, хотя в HTML-экспорте макета оно есть: внешний CDN на критическом пути рендера — лишний блокирующий запрос к чужому домену и передача IP каждого посетителя третьей стороне.

Конфигурация — блок `fonts` в [`vite.config.js`](../vite.config.js), провайдер `google()` из `laravel-vite-plugin/fonts`. Плагин скачивает woff2, кладёт их в `public/build`, собирает `@font-face`, `<link rel="preload">` и CSS-переменные `--font-unbounded` / `--font-manrope`. В шаблон это приходит директивой `@fonts` в layout — она стоит **до** `@vite`, чтобы preload попал в разбор раньше блокирующего CSS.

Три вещи, которые ломаются молча:

- **`subsets` обязан включать `cyrillic`.** Умолчание провайдера — `['latin']`, а сайт русский целиком. Без кириллического подмножества файл не содержит нужных глифов, браузер уезжает в системный шрифт, а `@font-face` и preload при этом на месте и выглядят рабочими. Проверять надо видом кириллического заголовка, а не наличием запроса за файлом.
- **Ссылка на переменную в `font-family` пишется с запасным именем семейства** — `var(--font-unbounded, 'Unbounded'), sans-serif`. Неопределённая переменная делает всю декларацию невалидной, и страница уезжает в шрифт браузера целиком.
- **`@fonts` при отсутствующем манифесте возвращает пустую строку** и не бросает исключение, в отличие от `@vite`. Тест на preload-ссылку (`LayoutTest`) зелёный только после `npm run build`.

Алиасы намеренно оставлены умолчательными (`unbounded`, `manrope`), а токены названы иначе (`--font-display`, `--font-sans`): иначе одну и ту же переменную на `:root` пишут двое — инлайновый стиль `@fonts` и блок `@theme`, — и кто выиграет, зависит от порядка тегов в `<head>`.

`fontaine` в `devDependencies` стоит ради умолчания `optimizedFallbacks: true`: он считает метрики шрифта и подгоняет под них системный фолбэк, чтобы подмена при `display: swap` не дёргала вёрстку.

## Тёмная тема

Тема одна. Светлой версии в дизайн-системе нет, и «автоматическая» светлая на тёмных токенах дала бы нечитаемый сайт.

`color-scheme: dark` в базовых стилях — не косметика: без него браузер красит нативные контролы по светлой схеме, и выпадающие списки формы заявки («способ связи», «удобное время») отрисуются светлыми. На светлой ОС это выглядит как сломанная форма, а на тёмной проблемы не видно вовсе. Туда же скроллбары и подсветка автозаполнения.

`@media (prefers-reduced-motion: reduce)` гасит анимации и переходы. Правило заведено вехой 4.1, хотя главный его повод — бегущая строка вехи 4.2: непрерывно ползущий через весь экран текст у человека с вестибулярными нарушениями вызывает тошноту, а выключить его нечем.

## Компоненты каркаса

| Компонент | Тип | Параметры |
| :---- | :---- | :---- |
| `<x-site-header />` | классовый, `App\View\Components\SiteHeader` | `:overlay` — `false` (по умолчанию) липкая шапка с размытием, `true` — прозрачная поверх хиро |
| `<x-site-footer />` | классовый, `App\View\Components\SiteFooter` | — |
| `<x-car-card />` | анонимный | `:car` — модель `Car`; `heading` — тег заголовка, `h2` по умолчанию |
| `<x-page-heading />` | анонимный | `title`, `eyebrow`, `intro`; заголовок можно передать слотом вместо `title` |
| `<x-lead-form />` | классовый, `App\View\Components\LeadForm` | `:source`, `title`, `submit`, `:parts` — только `<form>`, см. ниже |
| `<x-lead-section />` | классовый, `App\View\Components\LeadSection` | всё то же плюс `eyebrow`, `heading`, `text`, `background` — секция с раскладкой |

Шапка и подвал **читают настройки сайта сами** — это единственное исключение из правила «Blade не ходит в БД», и оно ограничено этими двумя компонентами. Layout рендерит их на каждой странице, и прокидывание контактов из каждого контроллера означало бы, что забытый контроллер даёт подвал без телефона молча и только на одной странице. Чтение идёт через кеш `Setting`: вся страница стоит один запрос к `site_settings` на холодном кеше и ноль на тёплом, на это стоит сторож в тестах.

**Страницы так не делают.** `ServiceController`, `PartsController` и `ContactController` читают настройки сами и передают в шаблон готовыми.

### Форма заявки: `x-lead-form` и `x-lead-section`

Компонентов два, и граница между ними проходит по `<form>`:

- **`x-lead-form`** — только `<form>` с полями, кнопкой, сообщением об успехе и необязательным заголовком. Собственной обёртки-контейнера у него нет: карточку с фоном, рамкой и отступами рисует вызывающая сторона. Иначе форма несла бы свой фон внутрь чужой карточки — подложка на подложке.
- **`x-lead-section`** — секция-обёртка с двумя раскладками: центрированная карточка (`heading` не задан) и две колонки на фоновом фото (`heading`, `eyebrow`, `text`, `background`). Внутри вызывает `x-lead-form`.

Обычной странице нужен **`x-lead-section`**. Напрямую `x-lead-form` вызывается только там, где форма встраивается в чужую карточку — так сделана заявка в правой колонке карточки автомобиля.

Разделение появилось вехой 4.3 по триггеру, названному вехой 4.2 дословно: третий вызов с раскладкой — повод вынести обёртку. Внутренности `<form>` при этом не изменились ни на строку: там инварианты вехи 3.7 (honeypot за пределами экрана, отсутствие клиентского `page_url`, `old()` во всех полях), и сторож здесь — `LeadStoreTest` с `SectionPagesTest`, обязанные проходить без правок.

**Якорь `#lead-form` живёт на обёртке, а не на самой форме.** На него ведут кнопка «Оставить заявку» в шапке (десктопной и мобильной) и умолчание `home.promo.link_url`, поэтому он обязан быть на странице ровно один — а секция заявки и карточка автомобиля встречаются вместе. В `x-lead-section` он на `<section>`, на карточке авто — на `<div>` с карточкой формы.

### Пагинация

Собственный вид — [`resources/views/pagination/catalog.blade.php`](../resources/views/pagination/catalog.blade.php), квадраты 40×40 по макету. Передаётся **именем** в `links('pagination.catalog')`; `Paginator::defaultView()` не используется — подробности и причина в [«Каталоге»](catalog.md).

### Alpine на публичных страницах

Компонент пишется **инлайном в `x-data`**, а не регистрируется через `Alpine.data()` из `@push('scripts')`. Ловушка неочевидная: `@vite` отдаёт `app.js` модулем из `<head>`, модуль исполняется отложенно и сам вызывает `Alpine.start()`. Скрипт, добавленный в конец `<body>` через `@push`, исполнится либо **раньше** модуля (обычный `<script>` — `window.Alpine` ещё нет), либо **позже** (`type="module"` — событие `alpine:init` уже отгремело, а после старта регистрация к разобранной разметке не применяется). Оба варианта ломаются молча: разметка и стили на месте, клики не работают.

Так написаны все три места с Alpine: мобильное меню шапки, авто-сабмит фильтров каталога и фотогалерея карточки. Стек `@stack('scripts')` в layout остаётся — но для скриптов, которым порядок Alpine безразличен.

Атрибуты событий пишутся полной формой (`x-on:click`, `x-on:change`), а не сокращением `@click`: `@` — префикс директив Blade, и сокращение живёт в шаблоне ровно до тех пор, пока имя события не совпало с именем директивы.

### Карточка автомобиля

`x-car-card` используется списком каталога и блоком похожих. В блоке похожих заголовок обязан быть `h3` (`heading="h3"`): иерархия заголовков — не оформление, по ней ходят скринридеры и по ней страницу разбирает поисковик.

Строка характеристик собирается из заполненных полей — пустое значение выпадает целиком, а не оставляет висящий разделитель. Пробег `null` выводится как «Новый»: это не «ноль километров», а автомобиль под заказ, у которого пробега нет вовсе.

Слово «привод» дописывает карточка, а не enum: подпись «Полный» полна в форме админки, где поле уже названо «Привод», и теряет смысл в строке «Электро · Полный · 67 769 км».

## Меню

Состав навигации живёт в [`app/Support/SiteMenu.php`](../app/Support/SiteMenu.php) — **одним списком на шапку и подвал**. Второй список разошёлся бы с первым на первом же новом разделе.

```php
'catalog.index'  => 'Каталог',     // шапка и подвал
'services.index' => 'Автосервис',  // шапка и подвал
'parts.index'    => 'Запчасти',    // шапка и подвал
'contacts.index' => 'Контакты',    // шапка и подвал
'about.index'    => 'О компании',  // только подвал, роут приходит вехой 4.5
```

Состав **намеренно расходится с макетом**: там «Каталог · Услуги · Блог · Контакты». Блог из проекта снят целиком, а его место заняли «Автосервис» и «Запчасти». При сверке вёрстки с макетом меню легко «поправить» обратно — не надо.

**Пункт без зарегистрированного роута выпадает, а не роняет страницу.** Причина не в снисходительности: шапка рендерится на каждой странице, и переименованный роут положил бы весь сайт вместе с формами заявок. Ошибка ловится тестом до мержа (`LayoutTest` проверяет, что все четыре роута зарегистрированы и попали в разметку). Это же закрывает переходный период: «О компании» появится в подвале автоматически, как только веха 4.5 заведёт роут `about.index`.

Активный раздел определяется по **имени роута с маской** (`catalog.*`), а не сравнением адресов: карточка `/catalog/{slug}` обязана подсвечивать «Каталог», и `url()->current()` этого не даёт.

## Как добавить страницу

1. Контроллер в `app/Http/Controllers/`, тонкий: получил данные, отдал в шаблон. Настройки читает он, а не Blade.
2. Роут в `routes/web.php` с именем по конвенции `<раздел>.index`.
3. Шаблон `resources/views/<раздел>/index.blade.php`:

```blade
@extends('layouts.app')

@section('title', 'Заголовок — '.config('app.name'))
@section('description', 'Описание для сниппета, до 160 символов.')

@section('content')
    <x-page-heading eyebrow="Раздел" :title="$title" :intro="$intro" />

    {{-- содержимое --}}

    <x-lead-section title="Оставить заявку" />
@endsection
```

Заголовок можно передать слотом, если внутри H1 нужно акцентное слово:

```blade
<x-page-heading eyebrow="Каталог">
    Автомобили в наличии и <span class="text-accent">под заказ</span>
</x-page-heading>
```

4. Если раздел попадает в меню — добавить его в `SiteMenu`. Пункт появится в шапке и подвале сразу, как только роут зарегистрирован.

Каркас даёт странице: шапку, подвал, `<main id="content">`, skip-link, `@yield('above-header')` под блок выше шапки и `@stack('scripts')` под собственный JS страницы.

## Логотип и favicon

Логотип лежит в `resources/images/logo-white.png` и проходит через манифест Vite (`Vite::asset('resources/images/logo-white.png')`): хеш в имени даёт вечный кеш и корректную инвалидацию при замене. Файл в `public/` пришлось бы сбрасывать у каждого посетителя вручную.

Ассет попадает в манифест благодаря `import.meta.glob(['../images/**'], { eager: true })` в `resources/js/app.js`. **`eager` обязателен**: ленивый вариант из документации Laravel даёт динамические импорты, которые никто не вызывает, и rolldown вырезает их вместе с ассетами — сборка остаётся зелёной, а файла в манифесте нет.

В репозитории лежит веб-копия 440×128 (8,5 КБ). Оригинал 3904×1135 (73 КБ) остался в `assets/Макет сайта «ЛАО КАРС»/`: он рисуется высотой 26–30px, и отдавать 73 КБ ради ста пикселей ширины на каждой странице незачем.

Favicon (`public/favicon.ico`) — знак-ромб из логотипа, 64×64 PNG внутри ICO-контейнера.

## Диагностика

**Сайт открылся без стилей, шрифт системный, вёрстка «рассыпалась».** Не собран фронтенд:

```bash
npm run build     # или `npm run dev` / `composer dev` для разработки
```

`@vite` в этом случае бросает исключение с понятным текстом. Если стили есть, а шрифт всё равно системный — смотрите следующий пункт.

**Стили на месте, но заголовки не в Unbounded.** Манифест шрифтов не собрался, а `@fonts` при его отсутствии молча возвращает пустую строку. Проверить:

```bash
cat public/build/fonts-manifest.json | head -5
```

Файла нет — пересоберите фронтенд. Файл есть, а кириллица всё равно системная — проверьте, что в `vite.config.js` у обоих семейств стоит `subsets: ['latin', 'cyrillic']`.

**Сборка падает или подвисает на скачивании шрифтов.** Плагин ходит на `fonts.googleapis.com` и кеширует результат в `node_modules/.cache/laravel-vite-plugin/fonts`. Повторная сборка в сеть не идёт. В CI под это заведён отдельный шаг `actions/cache` — `actions/setup-node` с `cache: npm` кеширует стор npm, а не этот каталог.

**Шапка без телефона, подвал без адреса.** Не заполнены настройки сайта — админка, «Настройки сайта», вкладки «Контакты» и «Соцсети». В `storage/logs/laravel.log` при этом пишется `WARN [Layout]` с именем незаполненного ключа. Пустая ссылка `tel:` не выводится вовсе: она выглядела бы рабочей.

**Пункт меню пропал.** Роут раздела не зарегистрирован — проверьте `php artisan route:list --except-vendor`. `SiteMenu` выводит только пункты с существующим роутом, поэтому страница не падает, а пункт исчезает.

**Пропали обводки карточек, полей формы и шапки, ошибок нет.** Из `@theme` исчезли `--color-white` и `--color-black` — их уносит `--color-*: initial`, и классы `border-white/8`, `bg-white/6` перестают собираться молча. Проверяется поиском `border-white` в `public/build/assets/app-*.css`.

**Кнопка «Оставить заявку» в шапке скроллит не туда.** На странице два элемента с `id="lead-form"` — якорь ведёт на первый попавшийся. Он живёт на обёртке (`x-lead-section` или карточка формы), и на странице должен быть ровно один: `document.querySelectorAll('#lead-form').length`.

**Alpine-компонент не работает: разметка и стили на месте, клики нет.** Скрипт зарегистрирован через `Alpine.data()` из `@push('scripts')` — так он исполнится либо раньше `app.js`, либо после `alpine:init`. Компонент публичной страницы пишется инлайном в `x-data`.
