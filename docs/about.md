# Страница «О компании»

Из чего собрана страница `/about`, какие настройки ею управляют, откуда берутся команда и отзывы, почему у неё есть сервис-прослойка и почему отзывы здесь показываются без лимита главной.

Страница появилась вехой 4.5 — первой половиной вехи «О компании и контакты». Вторая половина, [страница контактов](contacts.md), свёрстана позже и по тем же кирпичам.

## Из чего собрана страница

Данные собирает `app/Services/AboutPageContent.php`, контроллер `AboutController` только отдаёт их в шаблон `resources/views/about/index.blade.php`. Blade в базу не ходит.

| Блок | Фон | Откуда данные | Если данных нет |
| :---- | :---- | :---- | :---- |
| Шапка страницы: надзаголовок, H1, вступление | светлый | настройки `about_page.intro_title`, `about_page.intro_text` | H1 откатывается на «О компании», вступление исчезает |
| Наша история | светлый | настройка `about_page.history` (репитер) | блока нет |
| Миссия | светлый, на тон темнее | настройка `about_page.mission` | блока нет |
| Команда | светлый | опубликованные карточки раздела «Команда» | блока нет + WARN в лог |
| Отзывы | светлый, на тон темнее | опубликованные отзывы раздела «Отзывы» | блока нет |
| Секция заявки | светлый | компонент `x-lead-section` | не бывает пустой |

Страница светлая целиком, как остальные внутренние (веха 4.11). Оттенков ровно два и они чередуются: `page` → `page-alt` → `page` → `page-alt`. Механика — в [дизайн-системе](design-system.md#две-темы-тёмная-по-умолчанию-и-светлые-секции).

**Пустой блок не рендерится пустым — он не рендерится вовсе.** Заголовок «Команда» над пустой сеткой читается не как «мало контента», а как поломка сайта.

**Единственное исключение — на уровень ниже.** Пустая *карточка* сотрудника не рендерится, а карточка без *фотографии* рендерится с заглушкой. Разбор — ниже, в разделе про команду.

## Что правится в админке

Тексты страницы живут на странице **Настройки сайта → вкладка «О компании»**. Вкладка своя, седьмая.

| Поле в админке | Ключ настройки | Что это на странице |
| :---- | :---- | :---- |
| Заголовок страницы | `about_page.intro_title` | H1 и заголовок вкладки браузера. Пустое значение возвращает умолчание «О компании» |
| Вступление | `about_page.intro_text` | Абзац под H1 |
| Миссия: заголовок | `about_page.mission.title` | Заголовок блока миссии |
| Миссия: текст | `about_page.mission.text` | Текст блока миссии |
| История → Год / Заголовок / Текст | `about_page.history` | Карточки блока «Наша история». Порядок содержателен — вехи идут по времени |

**Почему вкладка своя, а не «Автосервис и запчасти».** Соседняя вкладка называется именно так, а не «Страницы»: её имя намеренно не трогали при переименовании пунктов меню (разбор — в [дизайн-системе](design-system.md#меню) и в [спецификации](../.ai-factory/DESCRIPTION.md)). Дописать ключи страницы «О компании» под заголовок про автосервис значило бы положить их туда, где заказчик их не найдёт.

**Команда и отзывы здесь не настраиваются.** У них свои разделы админки — **Контент → Команда** и **Контент → Отзывы**, — а дублирующее поле в настройках означало бы два места правки одного и того же. Как заводить карточки сотрудников, описано в [«Контент и настройки»](admin-content.md) и в справке самой панели.

### Поведение при пустых значениях

| Что очистили | Результат |
| :---- | :---- |
| Заголовок страницы | H1 и `<title>` показывают «О компании» — умолчание, а не пустой тег |
| Вступление | Абзаца нет, шапка остаётся |
| Заголовок **и** текст миссии | Блока миссии нет целиком |
| Только заголовок или только текст миссии | Блок остаётся с тем, что заполнено |
| Заголовок отдельной вехи истории | Эта карточка выпадает, остальные остаются |
| Год отдельной вехи | Карточка остаётся без года: веха без даты остаётся вехой |
| Все вехи истории | Блока «Наша история» нет |
| Все карточки команды сняты с публикации | Блока «Команда» нет + WARN в лог |
| Все отзывы сняты с публикации | Блока «Отзывы» нет, без WARN |

**Почему у пустой команды WARN, а у пустых отзывов нет.** Сотрудники заведены вехой 3.2, панель к ним есть, и пустой список означает незаполненную админку, а не выключенный блок. Отзывов может не быть просто потому, что их ещё не собрали. Снаружи оба случая выглядят одинаково — страница отдаёт 200 и кажется работающей, — поэтому разница вынесена в лог:

```
[О компании] на странице нет ни одного опубликованного сотрудника — блок «Команда» не выведен
```

## Команда

Карточки берутся из модели `Employee` скоупами `published()->ordered()` с обязательным `with('media')`.

**`with('media')` — не оптимизация «на всякий случай».** Без него каждая карточка добавляет запрос к базе за фотографией, то есть сетка из восьми человек стоит девять запросов вместо двух. Требование записано дословно в PHPDoc `Employee::photoUrl()`, а сторож против N+1 стоит в `AboutPageTest`: он сравнивает число запросов на маленькой и большой выдаче и требует равенства.

Страница — **первый и единственный потребитель `Employee`**. Модель и панель к ней завели вехами 3.2 и 3.5 авансом под эту веху; до неё сотрудники не выводились нигде.

### Заглушка вместо фотографии

Карточка без снимка показывает серый прямоугольник той же формы и размера, что и фотография, с первой буквой имени внутри.

Это не украшение и не вкус. Справка сотруднику (`resources/help/team-page.md`) обещает дословно: «Карточка без фотографии выглядит нормально — на её месте показывается заглушка». Приём карточки отзыва на главной — нет фото, нет тега `<img>` — скопировать сюда нельзя: он превратил бы статью справки в ложь в момент открытия страницы, а сетка из карточек разной высоты выглядела бы сломанной.

Заглушка и снимок делят одну геометрию: высоту и скругление задаёт обёртка, а не каждый из двух по отдельности, иначе они разъедутся при первой правке одного из них. Токен подложки — `bg-photo`, тот же, что под фото отзыва, и он же стоит подложкой в макете.

Сторож — тест `renders a placeholder instead of the photo for an employee without one`. Без него статья справки и поведение расходятся молча.

## Отзывы

Те же данные и тот же способ выбирать, что на главной: модель `Review`, скоуп `published()->ordered()`, загрузка `with('media')`. Разметка карточки повторяет главную намеренно — вторая вёрстка одних и тех же данных разъехалась бы с первой.

**Разным остаётся объём: здесь выводятся ВСЕ опубликованные отзывы, без лимита главной.**

Лимит `home.reviews_limit` (по умолчанию 3) заведён с прямой оговоркой, что на этой странице его быть не должно. `config/home.php` формулирует это дословно: «Полный список отзывов — задача страницы „О компании“, а не главной». Взять лимит сюда значило бы противоречить обоснованию собственного конфига.

Если потолок здесь всё же понадобится — например, отзывов накопится сотня, — он заводится **своим** ключом `about.reviews_limit`, а комментарий в `config/home.php` правится тем же коммитом. Два противоречащих утверждения в конфиге и в коде переживут любого, и победит то, которое прочтут вторым.

Общий способ выбирать при этом обязателен: второй разошёлся бы с первым, и посетитель увидел бы на двух страницах разный порядок одних и тех же отзывов.

## Почему у страницы есть сервис

`ARCHITECTURE.md` разрешает контроллеру читать модель напрямую, когда речь про чистое чтение и прослойка была бы пустым файлом. Граница названа там же: **сервис появляется, когда данные надо приводить к форме, прежде чем отдать их в Blade** — даже если запрос один.

У этой страницы три источника (группа настроек, сотрудники, отзывы), и два из них требуют приведения к форме:

- **репитер истории** при удалении всех элементов приходит `null`, а не `[]`. Шаблон, написанный по сиду, упал бы на первом же `foreach (null)` — на проде, где настройки правят, а не в тестах;
- **миссия** — настройка-объект, у которой оба поля могут оказаться пустыми, и блок исчезает только когда пусты оба.

Плюс `with('media')` у обеих выборок и фолбэк заголовка на очищенную настройку.

**Пара «автосервис / запчасти» разведена по обе стороны той же границы**, и без этого объяснения третий случай читается как произвол:

| Страница | Сервис | Почему |
| :---- | :---- | :---- |
| `/services` | `ServicesPageContent` | Группировка прайса по категориям, отсев пустых, две настройки-объекта, нормализация репитера |
| `/parts` | нет, намеренно | Один запрос и три текстовых ключа — прослойка была бы пустым файлом |
| `/about` | `AboutPageContent` | Три источника, нормализация репитера и объекта, `with('media')` у двух выборок |

Причина записана в PHPDoc всех трёх контроллеров: без этого `PartsPageContent` однажды заведут «для порядка», а `AboutPageContent` однажды «упростят» обратно в контроллер.

## Секция заявки обязательна

Форма внизу страницы — не «за компанию с остальными разделами».

Кнопка «Оставить заявку» в шапке ведёт на `#lead-form` **на каждой странице сайта** — и в десктопной шапке, и в мобильном меню. Якорь появляется только вместе с компонентом `x-lead-section`. Страница без секции даёт мёртвую кнопку в шапке: без ошибок, без записи в лог, заметно только кликом.

Якорь обязан быть на странице ровно один — на это стоит отдельный тест.

Заголовок секции здесь отличается от умолчания: «Познакомиться» вместо «Оставить заявку». На странице, где человек только что прочитал про команду и историю, приглашение звучит уместнее требования. Формулировка остаётся открытым вопросом к заказчику; сам вопрос «нужна ли там форма» снят.

## Meta-теги

Заголовок вкладки собирается из настройки `about_page.intro_title`, описание для сниппета живёт в шаблоне — как у `/services`, `/parts` и `/contacts`.

Общий фолбэк на `seo.default_*` здесь **не применяется**, и это то же решение, что записано с другой стороны в PHPDoc `HomeContent::seo()`: главная — единственная страница, которая использует умолчания. У каталога, карточки авто и разделов свои осмысленные заголовки, и общий фолбэк там маскировал бы забытую секцию вместо того, чтобы её обнажить.

## Что взято из макета, а что нет

Экран About макета v1 (`assets/Макет сайта «ЛАО КАРС»/About.dc.html`) — единственный готовый макет из оставшихся страниц; контакты собираются по UI Kit. Из него взяты раскладка и порядок блоков: история → миссия → команда → отзывы.

**Цвета из макета не берутся вовсе**: он рисовался под тёмную тему, светлых значений в нём нет. Палитра приходит из токенов.

Три вещи не перенесены, и каждая не мелочь:

- **фотографический хиро страницы.** В макете H1 лежит на снимке команды или шоу-рума с градиентной маской. Снимка нет: тот, что пришёл вехой 4.5 в полосу доверия на главной, — чужой дилерский центр и подлежит замене (см. [«Главная страница»](homepage.md#фоновые-фотографии)). Ставить его вторым экраном значило бы повторить ту же неправду крупнее. Вместо хиро — `x-page-heading`, тот же компонент, что у остальных внутренних страниц;
- **состав меню шапки** («Каталог · Услуги · Блог · Контакты»). Навигация живёт в `App\Support\SiteMenu`, блог из проекта снят целиком. Макет v1 рисовался до этих решений;
- **H1 и заголовки блоков константами.** H1 приходит из настройки по тому же правилу, что на `/services` и `/parts`: заменить настройку константой из макета значит отобрать у заказчика поле, которое ему уже отдали на двух других страницах.

**История в макете — два абзаца прозой, здесь — репитер по годам.** Расхождение осознанное: прозу заказчик правит целиком и наощупь, а вехи добавляет по одной, и форма репитера уже есть у трёх блоков главной.

## Сторожа в тестах

| Файл | Что стережёт |
| :---- | :---- |
| `tests/Feature/Http/AboutPageTest.php` | H1 из настройки, фолбэк на очищенную настройку, публикация сотрудников и отзывов, отсутствие лимита главной, пустые блоки, заглушка фото, `null` в репитере, N+1, meta-теги, единственный якорь заявки |
| `tests/Feature/Http/SectionPagesTest.php` | Сквозное: `/about` отдаёт 200, заявка с неё доходит до базы, поля запчастей на неё не протекают |
| `tests/Feature/Http/LayoutTest.php` | Состав и порядок пунктов шапки, появление пункта в подвале |
| `tests/Feature/Filament/ManageSiteSettingsTest.php` | Совпадение реестра ключей с сидом, форма значения репитера истории и объекта миссии |
| `tests/Feature/View/PaletteGuardTest.php` | Палитра нового шаблона — подхватывает его автоматически, обходя все публичные blade-файлы |

**`/about` дописан в перечни `SectionPagesTest` вручную, и это важно знать.** Адреса там перечислены списком, и новая публичная страница сама в них не попадает: набор остался бы зелёным, а страница — единственной без трёх сквозных сторожей. Заводя следующую публичную страницу, пройдите по файлу поиском по `/contacts`.
