# Каталог: фильтры и контракт URL

Как устроен публичный каталог автомобилей: какие GET-параметры он понимает, как работает сортировка, что попадает в индекс поисковика и как завести характеристику, по которой можно фильтровать.

Страница живёт по адресу `/catalog`, карточка автомобиля — `/catalog/{slug}`.

> **Вёрстка каталога ещё не закончена.** Каркас, шапка, подвал и карточка автомобиля пришли вехой 4.1 — см. [«Дизайн-система и каркас вёрстки»](design-system.md). Сами страницы каталога остаются функциональными: форма фильтров и сетка характеристик существуют, чтобы фильтры проверялись на живой странице, а не только в тестах. Вёрстка фильтров, фотогалереи и микроразметки приходит вехой 4.3, до неё каталог в публичный релиз не идёт.

## Контракт GET-параметров

Все параметры необязательны, порядок значения не имеет.

| Параметр | Значения | Пример |
| :---- | :---- | :---- |
| `brand` | slug марки из справочника | `?brand=zeekr` |
| `engine` | `petrol`, `diesel`, `hybrid`, `electric` | `?engine=electric` |
| `year_from`, `year_to` | целое от 1950 до «текущий год + 1» | `?year_from=2023&year_to=2025` |
| `price_from`, `price_to` | целое, рубли | `?price_from=3000000` |
| `status` | `in_stock` или `on_order` | `?status=in_stock` |
| `attr[<ключ>]` | значение динамической характеристики | `?attr[body_type]=Кроссовер` |
| `sort` | `new`, `price_asc`, `price_desc` | `?sort=price_asc` |
| `page` | номер страницы | `?page=2` |

Полный пример: `/catalog?brand=zeekr&engine=electric&year_from=2023&price_to=5000000&attr[body_type]=Кроссовер&sort=price_asc&page=2`.

Марка передаётся slug-ом, а не идентификатором: id в адресной строке — мусор, который к тому же не переносится между окружениями.

**Динамические характеристики живут в пространстве имён `attr[]`, а не в плоских параметрах.** Ключ характеристики заводит администратор, и форма разрешает любой `snake_case` — включая `price`, `status`, `brand` и `sort`. Плоский `?body_type=Седан` читался бы приятнее ровно до того дня, когда кто-то заведёт характеристику с ключом `year`: фиксированный фильтр каталога тихо перестал бы работать. `attr[]` делает коллизию невозможной по построению.

### Что происходит с неправильными параметрами

- **Битый параметр уводит на чистый `/catalog`** — редиректом, а не ошибкой. Если из десяти параметров невалиден один, теряются все десять: для ссылки, которую в большинстве случаев прислал бот или сохранил браузер год назад, это правильный размен. Правила валидации намеренно широкие — типы и границы, а не бизнес-условия, — так что попасть под редирект осмысленным вводом трудно.
- **`?status=sold` не открывает проданные автомобили**, а отбрасывается валидацией: допустимых значений два, а не три. Проданные не выпадают из фильтра — они выпадают из выдачи; карточка при этом остаётся доступной по прямой ссылке ради истории и SEO.
- **Перевёрнутый диапазон нормализуется перестановкой.** `?year_from=2025&year_to=2020` показывает автомобили 2020–2025, а не пустой каталог: это обычная ошибка пользователя в двух селектах.
- **`page` не валидируется.** Пагинатор сам приводит значение к числу; страница за пределами последней отдаёт **404**, когда записи есть. Пустая страница с кодом 200 — тонкий контент, который поисковик увидит и запомнит. На пустом каталоге правило не срабатывает: там пусто по существу, а не из-за номера страницы.
- **Значение вне списка допустимых даёт честный ноль,** а не молча снятый фильтр: «нашлось 11» там, где пользователь ждал сужения, хуже пустой выдачи.
- **Неизвестный ключ характеристики просто отбрасывается** — как и ключ характеристики, у которой не стоит флаг «в фильтре».

### Сортировка

| `sort` | Порядок |
| :---- | :---- |
| `new` (умолчание) | Сначала новые |
| `price_asc` | Сначала дешёвые |
| `price_desc` | Сначала дорогие |

«Цена по запросу» уезжает в конец **в обоих направлениях**: в PostgreSQL умолчание `NULLS` зависит от направления, и «сначала дорогие» без явного указания открывалось бы автомобилями без цены.

У каждой сортировки есть tie-breaker по идентификатору. Без него автомобили с совпадающим временем создания — а импорт партии карточек одним прогоном даёт ровно это — расползаются по страницам непредсказуемо: одна карточка попадает и на первую страницу, и на вторую, а другая не попадает никуда.

## Индексация фильтров

Комбинаций фильтров сотни, и каждая даёт свой URL. Правило простое:

- **Канонический адрес списка** — `/catalog` плюс только `page`. Параметры фильтра из него выбрасываются, номер страницы — остаётся: у страницы 2 собственный канонический адрес, иначе её карточки не попадут в индекс никогда.
- **Любой применённый фильтр или неумолчательная сортировка** даёт странице `robots: noindex,follow`. `follow` обязателен — ссылки на карточки со страницы должны обходиться.
- **Пагинация под правило не подпадает.** Чистая вторая страница индексируется.
- `?sort=new` — тот же каталог, что и `/catalog`: уводить его в `noindex` не за что.

## Фильтруемые характеристики

Фильтровать можно по характеристикам двух типов: **«Выбор из списка»** и **«Да / Нет»**. Как завести такую характеристику — в [«Админка каталога»](admin-catalog.md); коротко:

1. Завести характеристику в разделе **Каталог → Характеристики авто**.
2. Выбрать тип «Выбор из списка» и заполнить список допустимых значений (для «Да / Нет» список не нужен).
3. Включить переключатель **«Показывать в фильтре каталога»** — у нефильтруемых типов он не показывается вовсе.
4. Проставить значения автомобилям в их карточках.

Ключ характеристики становится именем GET-параметра: `body_type` → `?attr[body_type]=Кроссовер`. **После создания ключ не меняется** — на нём держатся сохранённые пользователями и роботами ссылки.

**Флаг «в фильтре» гасится автоматически**, если тип характеристики меняют на текст или число. Это делает модель, а не форма: тип правится и из админки, и из сида, и из tinker, а три копии правила неизбежно разъедутся.

### Почему по тексту и числам фильтровать нельзя

Равенство по свободному тексту в фильтре бессмысленно: администратор пишет «Long Range AWD», пользователь такого не наберёт. Числу нужен диапазон, то есть приведение текстовой колонки к числу на каждой строке — запрос, который не покроет ни один индекс.

Диапазоны по числовым характеристикам («клиренс от 180 мм») отложены с названным триггером: первый запрос заказчика на такой фильтр — сигнал заводить отдельные типизированные колонки значений, а не подпирать текстовую.

### Что показывается в форме фильтра

Только варианты, по которым что-то найдётся: марка без доступных автомобилей в списке не появится, отсутствующий тип двигателя — тоже, а значения характеристики пересекаются с реально встречающимися. Вариант, дающий ноль автомобилей, — не «пустая выдача», а сломанное доверие к фильтру.

Счётчиков рядом с вариантами («Кроссоверов: 12») нет намеренно: честный счётчик обязан пересчитываться на каждую комбинацию — это фасетный поиск, а не фильтр каталога, — а нечестный обещает больше, чем показывает после клика.

## Похожие автомобили

Блок на карточке собирается двумя запросами: сначала автомобили той же марки, ближайшие по цене; если их не хватило — добор из других марок в коридоре ±30% от цены. У автомобиля без цены коридора не существует, поэтому для него добор идёт просто по свежим доступным — блок не пустеет.

Размер блока — `catalog.similar_limit`.

## Настройки

| Ключ конфига | Умолчание | Переменная окружения |
| :---- | :---- | :---- |
| `catalog.per_page` | 9 | `CATALOG_PER_PAGE` |
| `catalog.similar_limit` | 3 | `CATALOG_SIMILAR_LIMIT` |

Девять карточек — три ряда трёхколоночной сетки макета. Оба значения читаются через `env()` **внутри конфига**: вызов `env()` из контроллера после `php artisan config:cache` вернёт `null`.

## Индексы под фильтры

Каталог опирается на четыре индекса, заведённых миграцией `add_catalog_filter_indexes`:

| Индекс | Что обслуживает |
| :---- | :---- |
| `cars_available_created_index` | Выдача по умолчанию и пагинация |
| `cars_available_brand_index` | Фильтр по марке вместе с умолчательной сортировкой |
| `cars_available_price_index` | Диапазон цены и сортировка по ней |
| `car_attribute_values_filter_index` | Фильтр по динамической характеристике |

Три первых — частичные, с предикатом `status IN ('in_stock', 'on_order')`: он записан **тем же списком**, каким его строит выборка доступных автомобилей. Планировщик выводит `status = 'in_stock'` из этого списка, а `status <> 'sold'` — уже нет.

**Индекс по характеристикам построен по выражению `left(value, 64)`, и запрос повторяет это выражение.** Обычный индекс по колонке завести нельзя: запись b-tree ограничена 2704 байтами, а значение характеристики — `text`, куда вставленная копипастом комплектация ляжет целиком и уронит вставку. Поэтому запрос идёт двумя условиями: префикс сужает по индексу, точное равенство подтверждает совпадение.

Отсюда два правила, которые легко нарушить «упрощением»:

- **Условие `left(value, 64) = ?` убирать нельзя.** Выдача останется верной, а индекс молча выключится — регрессия, которую не поймает ни один функциональный тест. Её стережёт отдельная проверка `toSql()`.
- **Длину префикса нельзя поменять правкой константы.** `App\Support\AttributeFilterIndex::PREFIX_LENGTH` берут и миграция, и запрос; правка константы не пересоздаёт индекс, и запрос просто перестанет его брать. Менять длину можно только новой миграцией. Расхождение стережёт проверка по `pg_indexes`.

Кеша у вариантов фильтра нет: несколько лёгких запросов на показ каталога дешевле, чем инвалидация, завязанная сразу на три модели. Триггер пересмотра конкретный — каталог за тысячу карточек либо заметная доля времени ответа на этих запросах.

## Диагностика

**Фильтр по характеристике ничего не находит, хотя значения проставлены.** Проверьте флаг «Показывать в фильтре каталога» у характеристики и совпадение значения со списком допустимых — регистр и опечатки значимы.

**Переключателя «Показывать в фильтре каталога» нет в форме.** Тип характеристики — текст или число, по ним фильтровать нельзя.

**Ссылка с фильтром открывает пустой каталог без фильтров.** Один из параметров не прошёл валидацию — например, марка была переименована или удалена. Это штатное поведение, а не ошибка.

**Вторая страница показывает выдачу без фильтров.** Ссылка построена без сохранения query-строки. Все ссылки пагинации обязаны нести параметры фильтра.
