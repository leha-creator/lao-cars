# Справка в панели — ЛАО КАРС

Статьи для **сотрудника**, а не для разработчика. Читатель — администратор или менеджер,
пришедший с вопросом «что мне нажать». Он не знает слов «миграция», «настройка», «очередь»
и не должен узнать их из справки.

Устройство раздела (реестр, сервис, страницы, маршруты, рендеринг) описано для
разработчика в [`docs/help-center.md`](../../../docs/help-center.md). Этот скилл —
про то, как написать статью, и он на тот документ **ссылается**, а не пересказывает его:
скопированное обоснование расходится с оригиналом, и замечает это тот, кто пришёл
за инструкцией.

## Инварианты

Эти правила не обсуждаются. На каждое стоит сторож в `tests/Feature/Filament/HelpTest.php`,
кроме последнего — у него сторожа нет и быть не может.

1. **Файл статьи начинается с `##`.** Заголовок первого уровня печатает сама страница
   панели, и `#` в файле дал бы его дважды. Ошибка рефлекторная: текст в `docs/`
   начинается именно с `#`, и копирование оттуда приносит `#` с собой.
2. **Ссылок на другие статьи внутри текста нет.** Относительная ссылка резолвится
   от текущего адреса и ломается от лишнего слеша; абсолютная зашивает слаг в текст, где
   его не найдёт ни один сторож. Связи объявляются полем `related` и печатаются блоком
   «См. также». Ссылки на внешний мир (публичный сайт, Яндекс.Карты) разрешены — они
   не про наши слаги.
3. **Статья заканчивается разделом «Что увидит посетитель».** Без него инструкция
   описывает нажатия, а не смысл.
4. **Слаг = имя файла.** `resources/help/<слаг>.md`, всегда.
5. **Правка панели правит статью тем же коммитом.** Автоматического сторожа у этого нет:
   сравнить поведение кода и текст инструкции машинно нечем. Инструкция, отставшая
   на две вехи, вреднее её отсутствия, потому что ей верят.

## Что в тексте запрещено

Это правило, а не пожелание. Запрещены:

- команды оболочки и artisan;
- переменные окружения;
- имена файлов, таблиц, классов и **ключей настроек**;
- коды ответа HTTP;
- очереди, логи, названия пакетов.

Всё называется тем, что человек **видит на экране**: пункт меню, подпись поля, текст
кнопки. Путь пишется словами: **Настройки → Настройки сайта → вкладка «Контакты»**.

Причина не в снисходительности к читателю. Техническая подробность в справке — это второй
источник истины про устройство системы, который расходится с `docs/` и с кодом.

Диагностика формулируется как «что проверить» и «когда звать разработчика»:

> Уведомления не приходят → проверьте два переключателя в профиле и разрешение браузера →
> если не помогло, это к разработчику.

Без слова VAPID, без имени очереди, без кода ответа.

Подробнее, с примерами «до/после» на реальных абзацах →
[references/writing.md](references/writing.md)

## Структура статьи

Два вида статей, по числу разделов справки. Раздел выбирается по вопросу, с которым
человек пришёл, а не по тому, где живут поля.

| Раздел | Вопрос читателя | Форма статьи |
| :---- | :---- | :---- |
| `HelpSection::Scenarios` — «Сценарии работы» | «мне надо сделать X» | путь → шаги → что проверить |
| `HelpSection::Settings` — «Настройка параметров» | «какое поле что делает» | справочник полей по секциям |

Один и тот же экран может описываться обеими — это не дубль. «Обновить контакты компании»
и «Контакты, соцсети и подвал» разбирают одну вкладку: первая по шагам после переезда,
вторая по полям. Дописать сценарий в справочник значило бы получить статью, которую
открывают с двумя вопросами и оба раза читают лишнюю половину.

Скелет сценария:

```markdown
## Когда пригодится эта статья
## Куда идти            ← путь словами + снимок
## Шаг 1. …
## Шаг 2. …
## Если что-то не сошлось   ← «что проверить», «когда звать разработчика»
## Что увидит посетитель    ← обязателен
```

## Как добавить статью

Три шага, все обязательны — иначе покраснеет сторож.

**1. Запись в реестре** (`HelpLibrary::build()`). Порядок объявления = порядок в списке,
и он содержателен: «С чего начать» стоит первой.

```php
new HelpArticle(
    slug: 'contacts-update',
    title: 'Обновить контакты компании',
    summary: 'Одна фраза под заголовком и на карточке в списке.',
    section: HelpSection::Scenarios,
    gate: ManageSiteSettings::class,   // null — видно всем сотрудникам
    related: ['contacts-and-footer'],  // слаги, а не заголовки
),
```

**2. Файл текста** — `resources/help/contacts-update.md`.

**3. Обратная связь** — если связь двусторонняя, добавить свой слаг в `related` соседа.

Регистрировать что-либо в провайдере панели не нужно.

## Видимость по ролям

`gate` — это класс ресурса или страницы Filament, у которого спрашивается
`canAccess()`. **Второй матрицы прав не заводится**: список ролей в реестре разошёлся бы
с политиками при первом же изменении прав, причём в худшую сторону — статья про настройки
осталась бы видна менеджеру, который в настройки уже не ходит.

Правило выбора простое: **ключ доступа — это тот раздел панели, который статья
описывает.** Статья живёт в «Сценариях работы», а правится всё на странице настроек
сайта? Ключ всё равно от настроек сайта, а не `null`.

## Снимки экрана

Скриншоты в справке появились вехой 4.15 и **отменили** записанное до этого решение
«скриншотов нет». Регламент целиком, включая ловушки съёмки →
[references/screenshots.md](references/screenshots.md)

Коротко, чтобы не открывать файл ради одной строки:

- файлы — в `resources/help/screenshots/`, **не в `public/`**;
- имя — **по экрану**, не по статье (`settings-schedule.png`);
- разметка — только markdown, `alt` обязателен:
  `![Блок «Часы работы»: семь дней недели](/admin/help/image/settings-schedule.png)`;
- снимается **фрагмент**, светлая тема, ширина 900–1200, вес до 300 КБ;
- **в кадре не должно быть персональных данных клиентов.**

## Проверка перед сдачей

```
php vendor/bin/pest tests/Feature/Filament/HelpTest.php tests/Feature/Http/HelpScreenshotTest.php
```

Что покраснеет и почему:

| Сторож | Что вы забыли |
| :---- | :---- |
| `has a non-empty file for every registered article` | завести файл текста |
| `registers every file lying in the help directory` | убрать файл после переименования слага |
| `points every related slug at a registered article` | опечатка в `related` |
| `starts no article file with a first-level heading` | начали файл с `#` |
| `registers exactly the planned number of articles per section` | поправить число в самом тесте — оно и есть сторож |
| `has a file for every screenshot referenced from an article` | положить снимок |
| `references every screenshot lying in the screenshots directory` | убрать осиротевший снимок |
| `writes every screenshot address in exactly one form` | опечатка в адресе картинки |
| `gives every screenshot a non-empty alt text` | подпись к картинке |
| `keeps every screenshot under the weight ceiling` | снимок тяжелее 300 КБ |

Добавили статью с ключом доступа — проверьте ещё два набора вручную:
`forbids a manager from opening a closed article by its direct address` и сторож списка
того раздела, куда статья попала.
