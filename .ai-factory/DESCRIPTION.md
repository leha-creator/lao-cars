# ЛАО КАРС — сайт импорта авто и автосервиса (MVP)

## Обзор

«ЛАО КАРС» — компания с двумя направлениями бизнеса: импорт автомобилей (Китай, Европа и другие страны) и автосервисные услуги (ТО, ремонт, шиномонтаж, детейлинг, доп. сервисы).

Сайт закрывает обе линейки и работает как основной канал получения заявок: витрина каталога авто ведёт к заявке на конкретный автомобиль, страницы услуг — к записи на сервис. Все заявки со всех форм сходятся в единый список лидов в админке.

Источник требований: [ТЗ_ЛАО_КАРС.md](../ТЗ_ЛАО_КАРС.md) (версия 1.0, июль 2026).

## Основные возможности

**Публичная часть:**

- **Главная** — hero с акцентом на импорт авто, CTA «Подобрать авто» / «Оставить заявку», подборка моделей из каталога по отметке «на главной», редактируемый блок преимуществ, блок доп. услуг, форма быстрой заявки.
- **Каталог автомобилей** — список авто в наличии и под заказ; карточка с фотогалереей, техническими характеристиками (марка, модель, год, двигатель, привод, пробег), историей авто, ценой и заявкой на конкретный автомобиль; фильтры по марке, типу двигателя, году, цене и статусу; пагинация; у каждой карточки собственный URL, meta-теги и микроразметка Product/Vehicle.
- **Доп. услуги** — три посадочные страницы (автосервис, детейлинг, дополнительные сервисы) на едином шаблоне «страница услуги»: заголовок, описание, список позиций с ценой или «цена по запросу», форма записи с указанием выбранной услуги.
- **О компании** — история и миссия, карточки сотрудников, отзывы клиентов с модерацией публикации.
- **Блог «Полезно»** — статьи с категориями (выбор авто, импорт, обслуживание Zeekr / Voyah / BYD и др.), страница статьи с похожими материалами. Включён в MVP в упрощённом виде как основной источник органического трафика.
- **Контакты** — адрес (Москва, ул. Осенняя, 17, корп. 1), телефон, e-mail, соцсети и мессенджеры, форма обратной связи.

**Админ-панель (Filament):**

- Каталог авто: CRUD, мультизагрузка фото, статусы (в наличии / под заказ / продан), отметка «показывать на главной».
- Услуги: CRUD по трём категориям, цены, описания.
- Блог: CRUD статей, категории, WYSIWYG-редактор, загрузка изображений.
- Команда и отзывы: CRUD сотрудников, модерация отзывов.
- Заявки/лиды: единый список со всех форм с указанием источника (конкретное авто, услуга, общая форма), статусы обработки (новая / в работе / закрыта), комментарии менеджеров.
- Настройки сайта: контакты, соцсети, тексты блока преимуществ, SEO-настройки по умолчанию.
- Медиабиблиотека: централизованное хранилище изображений с переиспользованием между разделами.
- Пользователи и роли: администратор и менеджер (менеджер видит заявки и каталог, но не настройки сайта).

## Технологический стек

- **Язык программирования:** PHP 8.3+ (локально 8.5)
- **Framework:** Laravel 13 (ТЗ фиксирует минимум 11)
- **База данных:** PostgreSQL 17
- **ORM:** Eloquent
- **Админ-панель:** Filament (CRUD, роли, медиабиблиотека поверх Laravel)
- **Frontend:** Blade + Alpine.js + Tailwind CSS — серверный рендер ради SEO каталога, Alpine только для локальной интерактивности (галереи, фильтры, формы)
- **Очереди:** Redis — отправка уведомлений вне HTTP-цикла; клиент — `predis/predis` (расширения phpredis нет ни в локальной сборке PHP, ни в образах CI)
- **Инфраструктура:** Docker + VPS, Nginx, деплой через GitHub Actions, бэкапы БД и медиа
- **Интеграции (MVP):** Telegram-бот для мгновенных уведомлений менеджеру о новой заявке

### Решения, принятые при настройке проекта

| Развилка из ТЗ | Решение | Обоснование |
| :---- | :---- | :---- |
| MySQL или PostgreSQL | **PostgreSQL** | JSONB под разнородные характеристики авто, частичные индексы под фильтры каталога, адекватный полнотекстовый поиск |
| Blade+Alpine или Vue | **Blade + Alpine + Tailwind** | Серверный рендер даёт SEO каталога и микроразметку без SSR-обвязки; фильтры остаются индексируемыми GET-параметрами |
| Блог: нужен ли в MVP | **Да, в упрощённом виде** | Основной источник органики по низкочастотным запросам про импорт; влияет на структуру меню, поэтому решается до дизайна |

### Отложено за пределы MVP

Раздел 2 ТЗ предполагает более широкий набор интеграций, но в MVP осознанно входит только Telegram-уведомление о заявке. Отложено на вторую фазу:

- Яндекс.Метрика / GA — аналитика по целям-заявкам.
- SMTP / email-уведомления как дублирующий канал лидов.
- Яндекс.Карты / 2ГИС на странице контактов — до подключения карта заменяется адресом и ссылкой на внешний маршрут.

Также вне MVP остаются идеи из раздела 6 ТЗ: онлайн-запись с календарём слотов, личный кабинет, избранное и сравнение авто, калькулятор растаможки, CRM-интеграция, мультиязычность, отслеживание доставки.

Подробные архитектурные правила — в [.ai-factory/ARCHITECTURE.md](ARCHITECTURE.md).

**Паттерн:** Layered Architecture (на конвенциях Laravel).

## Архитектурные заметки

- **Домены разделены по бизнес-линиям:** каталог авто и услуги — независимые модули, связанные только через сквозную сущность заявки.
- **Заявка (Lead) — единая сущность** с полиморфной привязкой к источнику (автомобиль, услуга или общая форма). Это прямо следует из требования «единый список заявок со всех форм с указанием источника» и избавляет от трёх параллельных таблиц заявок.
- **Услуга — единая сущность с категорией**, а не три отдельные модели: ТЗ описывает три подраздела на общем шаблоне, различающихся только категорией.
- **Уведомления — через очередь Redis**, а не синхронно в контроллере: отправка в Telegram не должна задерживать ответ формы и не должна терять лид при недоступности внешнего API.
- **Медиа — через централизованную медиабиблиотеку** с переиспользованием между каталогом, блогом и командой.
- **SEO — первого класса:** канонические URL карточек, meta-теги, микроразметка Product/Vehicle, серверный рендер списков каталога.
- **Роли** реализуются на уровне политик доступа: менеджер ограничен заявками и каталогом.

## Нефункциональные требования

- **Логирование:** уровень настраивается через `LOG_LEVEL`; заявки и доставка уведомлений логируются отдельно — потеря лида должна быть диагностируемой.
- **Обработка ошибок:** формы возвращают структурированные ошибки валидации; сбой внешнего API (Telegram) не приводит к потере заявки — запись в БД первична, уведомление вторично и ретраится.
- **Безопасность:** CSRF на всех формах, rate limiting на публичных формах против спама, валидация и ограничение типов загружаемых файлов, разделение прав администратора и менеджера, секреты (токен Telegram, доступ к БД) только в переменных окружения.
- **Производительность:** индексы под фильтры каталога, устранение N+1 при выдаче списков с фото, оптимизация и ресайз изображений автомобилей.
- **Адаптивность:** мобильная версия обязательна — основной трафик автотематики мобильный.
- **Резервное копирование:** регулярные бэкапы БД и медиа.

## Ответственность заказчика (из раздела 7 ТЗ)

- Наполнение каталога реальными карточками (фото, характеристики) — начинать параллельно с разработкой.
- Финальные тексты и статьи блога, съёмка и подготовка фото.
- Согласования и правки — обычно добавляют 20–30% к срокам.
