# Пустой src в колонках админки: ImageColumn считает относительный URL путём на диске

**Дата:** 2026-08-11 17:12
**Файлы:** app/Filament/Resources/Cars/Tables/CarsTable.php, app/Filament/Resources/Employees/Tables/EmployeesTable.php, app/Filament/Resources/Media/Tables/MediaTable.php, app/Filament/Resources/Media/Tables/MediaPickerTable.php, tests/Feature/MediaUrlTest.php
**Серьёзность:** high

## Проблема

После перевода диска `public` на относительные URL (см. патч
`2026-08-11-16.59.md`) превью в списках админки исчезли совсем.
В разметке оставалась пустая рамка:

```html
<div class="fi-ta-image">
    <img alt="" src="" style="height: 56px; width: 56px;">
</div>
```

Затронуты все четыре колонки с картинками: автомобили, сотрудники,
медиабиблиотека и её же таблица внутри модального окна выбора.

## Root Cause

`ImageColumn::getImageUrl()` (filament/tables) различает состояния так:

```php
if ((filter_var($state, FILTER_VALIDATE_URL) !== false) || str($state)->startsWith('data:')) {
    return $state;
}
// иначе — это путь на диске
if (! $storage->exists($state)) {
    return null;
}
```

То есть контракт колонки — либо **абсолютный** URL, либо **путь** на диске.
Третьего варианта нет, и относительный URL проваливается в ветку пути:
`Storage::disk('public')->exists('/storage/cars/thumbs/img_1842.webp')`
ищет файл по `storage/app/public/storage/cars/thumbs/…`, не находит
и отдаёт `null` — то есть пустой `src`.

Ошибка не в правке конфига, а в неявном допущении, на которое та опиралась:
«URL картинки одинаково устроен для всех потребителей». Потребителей
оказалось два с противоположными требованиями — браузеру на странице сайта
нужен относительный адрес, Filament и schema.org нужен абсолютный.

Отдельно стоит отметить, почему регрессия дожила до глаз пользователя:
до правки колонки показывали `http://localhost/storage/…` — тоже нерабочий
адрес, но непустой. Симптом сменился с «битой картинки» на «пустую рамку»,
а весь набор из 489 тестов остался зелёным: ни один не смотрел на `src`.

## Решение

Состояние колонок оборачивается в `url()` — хелпер берёт origin текущего
запроса, поэтому в админке на любом порту адрес получается рабочим:

```php
ImageColumn::make('mainPhoto.thumb_url')
    ->state(fn (Car $record): ?string => $record->mainPhoto === null
        ? null
        : url($record->mainPhoto->thumb_url))
```

Обёртка стоит именно в слое Filament, а не в аксессоре модели: аксессор
обслуживает в первую очередь публичные страницы, где относительный адрес
объективно лучше. Правило колонок обратно правилу сайта, и место правки
должно совпадать с местом, где действует ограничение.

Вариант «отдать Filament путь и диск» (`ImageColumn::make('thumb_path')
->disk('public')`) отвергнут: он теряет откат превью на оригинал при пустом
`thumb_path` и игнорирует колонку `disk`, которая хранится у каждой записи.

## Prevention

- Перед изменением формата значения, которое отдаёт аксессор модели,
  перечислять всех потребителей поимённо. Здесь их шесть
  (`CarPhoto::url`, `CarPhoto::thumb_url`, `Media::url`, `Review::photo_url`,
  `Employee::photo_url`, `HomeContent::promoImageUrl`), и вызовы из Filament
  в этот список не попали, потому что колонка обращается к аксессору
  строкой `'mainPhoto.thumb_url'` — grep по коду её не находит.
- Точечные строковые ссылки на атрибуты (колонки Filament, `with()`,
  `pluck()`) искать отдельным запросом: обычный поиск по имени метода
  их пропускает.
- Новый тест обязан падать на старом коде. Оба admin-теста были прогнаны
  с временно снятым фиксом: первый показал `/storage/…` вместо абсолютного
  URL, второй — тот самый `<img alt="" src="">`. Тест, не проверенный
  на падение, здесь бы ничего не стоил — весь остальной набор эту поломку
  пропустил.
- Пустой `src` — это класс отказов без следа: ни исключения, ни строки
  в логе, ни красного теста. Для таких мест assert на разметку
  (`not->toContain('src=""')`) ценнее assert на значение.
