# Абсолютный URL медиа от APP_URL ломает картинки при смене порта

**Дата:** 2026-08-11 16:59
**Файлы:** config/filesystems.php, app/Services/CarStructuredData.php, app/Providers/AppServiceProvider.php, tests/Feature/MediaUrlTest.php
**Серьёзность:** high

## Проблема

Ни одна картинка на сайте не отображалась. Браузер запрашивал
`http://localhost/storage/cars/img_1842.webp` и получал
`(failed) net::ERR_CONNECTION_REFUSED`, тогда как само приложение
обслуживалось на `127.0.0.1:8123`.

Симптом сбивал с толку тем, что все привычные подозреваемые были в порядке:
файлы лежали в `storage/app/public/cars/`, junction `public/storage`
резолвился, а прямой запрос по правильному порту отдавал файл:

```
curl http://127.0.0.1:8123/storage/cars/img_1842.webp → 200 image/webp 86590
```

## Root Cause

Диск `public` в `config/filesystems.php` собирал **абсолютный** URL:

```php
'url' => rtrim(env('APP_URL', 'http://localhost'), '/').'/storage',
```

`Storage::disk('public')->url()` — единственный источник адресов медиа для
всего проекта (`CarPhoto::url`, `CarPhoto::thumb_url`, `Media::url`,
`Review::photo_url`, `Employee::photo_url`, `HomeContent::promoImageUrl`),
поэтому одна строка конфига определяла хост и порт каждой картинки сайта.

Ошибочным было само допущение, а не значение переменной: «адрес, по которому
приложение отдаётся, всегда равен APP_URL». Оно держится ровно до первого
запуска не по умолчанию — `artisan serve --port`, Herd, туннель, превью-стенд,
проброс порта в контейнере. Здесь APP_URL остался `http://localhost` (порт 80,
где не слушает ничего), а сервер поднялся на 8123.

Ошибка класса «тихих»: подстановка консистентна, страница отдаёт 200,
в логах приложения пусто — сломанный URL виден только в консоли браузера.
Тесты её тоже не ловили: `CatalogShowTest` сверял разметку с тем же
`$photo->url`, то есть сравнивал ошибку с самой собой.

## Решение

URL медиа сделан относительным — браузер разрешает его от origin текущей
страницы, и он верен на любом хосте и порту без правки окружения:

```php
'url' => rtrim((string) env('ASSET_URL', ''), '/').'/storage',
```

Пустой `ASSET_URL` схлопывает выражение в `/storage`; заполненный оставлен
осознанным обходом для CDN, где домен статики отличается намеренно.

Вторая сторона правила: schema.org требует абсолютный адрес картинки,
поэтому в `CarStructuredData` относительный URL оборачивается в `url()`.
Хелпер берёт origin текущего запроса, а уже абсолютное значение
(вариант с CDN) возвращает как есть — обёртка безопасна в обоих случаях.

Третьим шагом добавлена диагностика в `AppServiceProvider`: вне прода
пишется `WARN`, если `ASSET_URL` уводит медиа на хост, отличный от адреса
запроса. Раньше такая рассинхронизация не оставляла следа в логах вообще.

## Prevention

- Абсолютный URL в конфиге — это утверждение «приложение всегда доступно
  по этому адресу». Для ссылок из письма или микроразметки оно оправдано,
  для `src` в разметке — нет: там относительный адрес и короче, и вернее.
- Тест на URL, который сравнивает разметку с тем же аксессором, что её
  породил, не проверяет ничего. Ожидаемое значение должно быть выписано
  строкой: `toBe('/storage/cars/img_1842.webp')`, а не `toContain($photo->url)`.
- При жалобе «картинки не грузятся» сначала разделять два слоя: отдаётся ли
  файл по прямому `curl` (диск, симлинк, права) и совпадает ли адрес в `src`
  с адресом страницы (генерация URL). `ERR_CONNECTION_REFUSED` вместо 404 —
  сразу второй слой: до сервера запрос не дошёл.
- Регрессия закрыта `tests/Feature/MediaUrlTest.php`: относительный адрес
  в разметке и абсолютный в JSON-LD проверяются раздельно — фикс, чинящий
  только одну сторону, ломает вторую молча.
