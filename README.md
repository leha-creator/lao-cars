# ЛАО КАРС

> Сайт импорта автомобилей и автосервиса: каталог, автосервис, запчасти и единый поток заявок в админке.

Компания работает по двум направлениям — импорт автомобилей (Китай, Европа и другие страны) и автосервис (ТО, ремонт, шиномонтаж, детейлинг, подбор запчастей). Сайт закрывает обе линейки и служит основным каналом получения заявок: карточка автомобиля ведёт к заявке на конкретное авто, страница автосервиса — к записи на сервис, страница запчастей — к заявке на подбор детали, а все обращения сходятся в один список лидов.

Разделы сайта: **Каталог · Автосервис · Запчасти · Контакты** — эти четыре пункта закреплены в меню; плюс «О компании». Блога в проекте нет — решение зафиксировано в [спецификации](.ai-factory/DESCRIPTION.md).

**Текущее состояние:** собраны каркас проекта (веха 3.1) и схема данных — модели, миграции, фабрики и сиды (веха 3.2) плюс динамические характеристики авто (веха 3.3). Ресурсы админки и публичные страницы — в работе, см. [роадмап](.ai-factory/ROADMAP.md).

## Требования

| Инструмент | Версия | Зачем |
| :---- | :---- | :---- |
| PHP | 8.3+ (разработка ведётся на 8.5) | Приложение |
| Composer | 2.x | Зависимости PHP |
| Node.js | 20.19+ или 22.12+ (разработка ведётся на 24) | Сборка фронтенда |
| Docker | с Compose v2 | PostgreSQL и Redis |

PHP и Node запускаются локально (например, через Herd). В Docker живут только базы данных: bind mount исходников в контейнер на Windows заметно бьёт по I/O на каждом запросе. Прод-образ приложения собирается отдельно.

Расширение `phpredis` не требуется — клиентом Redis работает `predis`.

## Быстрый старт

```bash
git clone https://github.com/leha-creator/lao-cars.git
cd lao-cars

cp .env.example .env
docker compose up -d
composer install
npm ci
php artisan key:generate
php artisan migrate
php artisan storage:link
php artisan db:seed
php artisan make:filament-user
```

**Важно:** в `.env` укажите `REDIS_PORT=56379`, если штатный порт 6379 занят локальной службой Redis (в `.env.example` он оставлен каноническим — из этого файла собирается CI).

`storage:link` обязателен: символическая ссылка `public/storage` в репозитории не хранится, и без неё фотографии каталога не отдаются по URL. `db:seed` наполняет базу демо-данными — без него каталог, прайс и настройки сайта пустые.

Запуск разработки — одной командой (сервер, воркер очереди, логи и Vite параллельно):

```bash
composer dev
```

Либо по отдельности:

```bash
php artisan serve        # http://localhost:8000
npm run dev              # или npm run build
php artisan queue:work   # обработка уведомлений о заявках
```

Админ-панель — по адресу `/admin`.

## Локальное окружение

`compose.yml` поднимает две службы:

| Служба | Образ | Порт на хосте |
| :---- | :---- | :---- |
| PostgreSQL | `postgres:17-alpine` | 5432 |
| Redis | `redis:7-alpine` | 56379 |

Redis смещён с 6379 намеренно: штатный порт на машине разработки занят нативной службой `redis-server`, которая поднимается заново после перезагрузки.

При первой инициализации том Postgres получает две базы: рабочую `laocars` и тестовую `laocars_testing`. Init-скрипты выполняются **только на пустом томе** — если тестовой базы не оказалось, пересоздайте окружение:

```bash
docker compose down -v
docker compose up -d
```

## Данные

| Таблица | Что хранит |
| :---- | :---- |
| `brands` | Справочник марок — источник списка для фильтра каталога |
| `cars` | Карточка автомобиля: фиксированные фильтруемые характеристики, цена, статус, SEO-поля |
| `car_photos` | Галерея карточки; главное фото — первое по `sort_order` |
| `car_attributes` | Справочник динамических характеристик: машинный ключ, подпись, тип, единица, группа, порядок, флаги «в карточке» и «в фильтре» |
| `car_attribute_values` | Значения характеристик у автомобиля: одна текстовая колонка, по одному значению на пару «авто — характеристика» |
| `services` | Единая сущность услуг и запчастей, различаются категорией |
| `leads` | Заявки со всех форм с полиморфным источником (авто, услуга или общая форма) |
| `lead_comments` | Комментарии менеджеров к заявке с историей и авторством |
| `employees`, `reviews` | Команда и отзывы для страницы «О компании»; отзывы публикуются только после модерации |
| `site_settings` | Редактируемые блоки, контакты, соцсети и SEO по умолчанию: ключ — значение (`jsonb`) с кешем в Redis |

Цена и пробег допускают `null`: это «цена по запросу» и «новый автомобиль», а не ноль.

**Динамические характеристики.** Всё, что не стало колонкой `cars` — «кузов», «цвет», «растаможен», — описывается строкой справочника `car_attributes` и хранится в `car_attribute_values` одной текстовой колонкой; тип (текст, число, «да / нет», выбор из списка) задаёт справочник и применяет на чтении. Допустимые значения типа «выбор из списка» лежат в `options` справочника, а не собираются `DISTINCT`-ом по значениям: иначе список для фильтра наполняется опечатками наполнителя. Читаются характеристики методами `Car::cardAttributes()` (сетка карточки, сгруппированная по группам справочника) и `Car::attributeValue($key)`; пишутся только через `Car::syncAttributeValues()` — там проверка значения по списку, нормализация и удаление записи при пустом значении. Оба метода чтения работают поверх загруженной связи, поэтому в списках запрос обязан идти с `with('attributeValues.attribute')`.

Машинный ключ характеристики (`body_type`, `customs_cleared`) — публичный контракт: по нему строятся GET-параметры фильтра каталога и обращения из шаблонов. Свободно правится подпись, а не ключ.

**Демо-данные.** `php artisan db:seed` создаёт 8 марок, 12 автомобилей во всех состояниях карточки (в наличии, под заказ, продан, без цены), 9 динамических характеристик с представителем каждого типа и 77 их значений по каталогу, 21 позицию прайса по всем пяти категориям, команду, отзывы (включая один на модерации) и настройки сайта из макета. Заполнение характеристик неравномерное намеренно: один автомобиль остаётся вовсе без них, чтобы карточка проверялась и на пустом наборе. Фотографии берутся из `assets/cars/` и копируются в `storage/app/public/cars/`.

Сиды идемпотентны — повторный запуск не плодит дубли. Полный сброс: `php artisan migrate:fresh --seed`. Демо-пользователь не создаётся в production.

## Тесты

```bash
php artisan test
```

Тесты идут в **реальные PostgreSQL и Redis**, а не в SQLite и array-драйверы — контейнеры должны быть подняты. Это осознанное решение: подмена драйверов скрыла бы ровно те ошибки сборки инфраструктуры, которые smoke-тесты и должны ловить. Изоляция от рабочих данных — через отдельную базу `laocars_testing` и отдельные номера баз Redis (см. `phpunit.xml`).

Копирование фотографий в тестах отключено: в `assets/cars/` 46 файлов на 128 МБ, и перекладывать их на каждом прогоне `RefreshDatabase` бессмысленно. Фото в тестах создаёт фабрика.

Если при `docker compose down` тесты продолжают проходить — значит они проверяют не то, что заявлено.

Форматирование кода:

```bash
php vendor/bin/pint          # исправить
php vendor/bin/pint --test   # только проверить
```

## CI

GitHub Actions (`.github/workflows/ci.yml`) на каждый push в `master` и каждый pull request поднимает PostgreSQL 17 и Redis 7 тех же версий, что и локально, и прогоняет: `composer install` → `npm ci` → `npm run build` → `pint --test` → `php artisan test`.

Статический анализ в базовый CI пока не входит.

## Стек

- **Backend:** PHP 8.3+, Laravel 13, PostgreSQL 17, Eloquent
- **Админ-панель:** Filament 5 на Livewire 4
- **Frontend:** Blade + Alpine.js 3 + Tailwind CSS 4, сборка Vite
- **Очереди и кеш:** Redis 7 (`predis`)
- **Тесты:** Pest 4

Серверный рендер выбран ради SEO каталога: списки и карточки должны индексироваться, а фильтры — оставаться обычными GET-параметрами. Alpine отвечает только за локальную интерактивность.
